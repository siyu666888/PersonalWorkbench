# 手写 Baseline Profile 规则（HRF 格式）——V1.6.4 / C1
#
# 为什么是手写：生成 Baseline Profile 需要真机或 Gradle Managed Device
# （Macrobenchmark + androidx.benchmark 插件），本机无 hypervisor，模拟器无法引导，
# 因此采用折中方案：用 ART 可读的 HRF 规则覆盖「冷启动 + 首次 Composition」路径。
# AGP 会把本文件编译进 APK 的 assets/dexopt/baseline.prof，安装时随包下发，
# dex2oat 直接预编译这些类/方法，减少 JIT 解释执行与后台编译开销。
#
# 规则来源（非拍脑袋）：先用 build-tools 的 dexdump 导出 debug APK 全部 dex 的类名清单，
#     Class descriptor 列表 → 排序去重 → 本文件每条规则均在其中存在
# 维护约定：
#   1. 只写「类级规则」（L全限定名;），不写方法签名——方法签名极易随依赖升级失效；
#   2. 新增类必须是**确认真存在**的（跑一次上面的 dexdump 比对），不要凭印象；
#   3. TODO：具备真机/模拟器条件后，改用 Macrobenchmark 实测生成 + 本文件作兜底，
#      Gradle Managed Device 方案见 docs/ROADMAP.md C1。
#   4. 启用 R8 后（release）AGP 会按 mapping 自动重写这些规则为混淆后名字，
#      因此这里写的是**源码名**，不要手抄 mapping.txt。
#
